# BUILD-2026-09-13-r14.md — Round 14: P2.2 Telegraphs (Forge)

## What changed

**2 files: `game/systems/ai.py`, `game/systems/combat.py`**

### The bug
`ai.py` already had telegraph windup code for all 4 monster behaviors, but only the brute's
`pending_slam` mechanism actually fired the attack when the windup expired. The other three
behaviors (chaser, ambusher, ranged) set `mon.telegraph`, it decremented to 0 in `monster.tick()`,
and then the AI just re-set it again — an **infinite windup loop** where the monster never
actually attacked. Result: zero monster melee damage in headless runs despite monsters being in
range and "attacking."

### The fix

**`game/systems/ai.py`:**
- `_chaser`: added `pending_strike` flag — when telegraph expires (>0→≤0), fires
  `combat.monster_contact_attack(world, mon)` instead of re-setting the telegraph
- `_ambusher`: same — `pending_strike` flag fires `monster_contact_attack`
- `_ranged`: added `pending_shot` flag — when telegraph expires, fires
  `combat.monster_ranged(world, mon)` (spawns projectile)
- `_brute`: reordered `pending_slam` check to come **before** the telegraph-setting block
  (was after it and unreachable — same infinite-loop bug)

**`game/systems/combat.py`:**
- `monster_ranged`: added `mon.attack_timer = mon.attack_cooldown()` at the top (was missing —
  without it, ranged monsters re-telegraphed immediately after firing)

### Pattern (all 4 behaviors now follow this)
1. `if telegraph > 0: return` — monster frozen during windup, red glow visible (renderer.py:243-248)
2. `if pending_flag: clear it, fire attack, return` — telegraph just expired, attack fires
3. `if in range and attack_timer ≤ 0: set telegraph + pending_flag, return` — start new windup
4. Otherwise: approach/retreat/strafe

The player can dash away or pre-position during the windup (0.25s chaser, 0.35s ranged,
0.40s ambusher, 0.55s brute).
