## The tooling the questions exposed

### 1. The art lane had no licence gate (the audio lane does)

`docs/AUDIO-LICENSES.md` + `COMMERCIAL_OK_LICENSES` enforce music licensing in code. Art had nothing —
no ledger, no refusal, no way to answer "may we ship this". Added:

- `docs/ART-LICENSES.md` — ledger; every licence read from the HuggingFace registry API
  (`/api/models/<repo>` → `cardData.license`), never from a model card or memory.
- `tools/art/gen.py` — `ART_COMMERCIAL_OK`, `ART_BACKENDS`, and `--licence-board`:

```
$ python -m tools.art.gen --licence-board
art licence board - verified via the HuggingFace registry API, not model cards
  commercial-ok licences: apache-2.0, bsd-3-clause, cc0-1.0, mit, unlicense
  flux_schnell     black-forest-labs/FLUX.1-schnell   apache-2.0    SHIPPABLE wired
  dreamshaper_lcm  Lykon/dreamshaper-7    creativeml-openrail-m     REFUSED   not wired
```

`tools.art.verify` unchanged: 414 sprite file(s), 391 frame(s), 0 off-palette pixel(s).

### 2. A thinking VLM scored 0/5 because of *our* harness

`glm-4.6v-flash` first scored 0/5 with no answers printed at all. The raw API response showed why:
`content: ''`, `finish_reason: length`, **all 299 completion tokens in `reasoning_content`**, mid
sentence. A reasoning model bills its chain-of-thought against `max_tokens`. With a real budget it
scored 3/5. `tools/qa/vlm_bench.py` now reports `finish_reason` and `reasoning_tokens`, auto-escalates
a truncated reply instead of scoring it, says *"this is a harness limit, NOT a vision failure"*, and
persists raw answers — I needed the raw text twice this round and it was not being saved.

### 2b. Correction, same round: the "2/5" for glm-4.6v-flash was my truncation

I recorded glm-4.6v-flash as **2/5**, then read the raw answer the harness had persisted:

```
1. 16          <- correct
2. 5           <- correct
(finish_reason: length - 2035 reasoning tokens ate the 2048 budget here)
```

It was **cut off mid-answer** before questions 3-5. Both answers it gave were right and the score said
otherwise. With `--max-tokens 8192` (`finish=stop`, complete) it scores **3/5**, reproduced twice:
Q2/Q3/Q4 correct, Q1 off by one (15 vs 16), **Q5 wrong — it denies the flat rectangles**.

The verdict (no — 11× slower, blind to the defect class that matters) survives, but the recorded number
was an artefact of my instrument. `vlm_bench` now **auto-escalates the budget** when a reply is
truncated and prints `[WARNING] any score below is a FLOOR, not a verdict` if it still is, so a partial
answer cannot masquerade as a capability result. Reading the raw output is what caught this — a harness
that persisted only the score would have hidden it permanently.

### 3. `bench_local` reported a traceback where it should have reported a fact

Both text candidates came back as `HTTPError: HTTP Error 400`, indistinguishable from a broken model.
The real message was "this model does not fit at this context". Now prints LM Studio's own error body
plus what it means and what to try. Its own new error path then failed with `NameError` (a variable not
in scope) — found by **forcing** the failure and reading the output, which is the only way an error
branch gets tested.

Then the *root* cause turned up underneath, while re-measuring: `load()` computed an `ok` flag, printed
`load FAILED`, and **carried on anyway** — the check existed and was never wired to anything, so a
failed load always surfaced as a confusing completion error instead of the reason. It now returns
`(ok, detail)`, requires positive evidence (`"Model loaded"` in the output — `lms load` can exit 0
while reporting a failure), and `main()` aborts with LM Studio's own words. Forced-failure output:

```
  load FAILED in 0.3s (VRAM 921 MiB, 12227 MiB)
REFUSED: could not load no/such-model-xyz at context=8192.
  LM Studio said: To select a model interactively, remove the --yes flag ...
  Means: the model does not fit the card at this context, or the model id is wrong.
```

Finally, it now **persists its measurements** (`%TEMP%/rw_bench_local.json`, merge-keyed by
`model@context`, atomic write) — the numbers in `docs/MODELS.md` had no artefact behind them, which is
the same "a benchmark with no file on disk is a claim" rule the VLM harness was just fixed for. A
re-run at a different `--tokens` also showed the rate moves (40.1 tok/s @150 vs 45.1 @200), so the docs
quote a range.

### 4. The gate suite was red for a reason that meant nothing

`selftest` went 19/20 → 13/20 mid-round. Two separate defects:

- **Six healthy checks marked FAIL** while their tools exited 0. `_util.run_tool_subprocess` parsed
  stdout line-by-line expecting single-line JSON, but the tools pretty-print (`indent=2`): it found a
  line starting with `{`, failed to parse, and reported the last output line (`}`) as the error.
  Replaced with whole-output parse + last-balanced-object scan.
- **`golden-seed-regression`: 500 findings, all artifacts.** The new balance gate tested
  `damage/armor/crit/value` dominance, but `items.json` has **no combat stats at all** (all 73 entries
  score zero — the schema is `slot/effect/value/tier`), so the rule silently degenerated into comparing
  **price**, and treated a *higher price* as better. Every one of the 500 findings was "this item costs
  more". Rewritten to discover the schema, compare same-slot items only, require `<=` on cost, and
  **SKIP with the measurement** when the data cannot support the claim.

A permanently-red gate is worse than no gate: it trains everyone to ignore the suite.
