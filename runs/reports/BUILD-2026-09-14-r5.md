## What changed

Modding-lite: expose `game/data/` overrides from a user folder. Everything data-driven
already; this adds `--data-dir` and `--mod-dir` CLI flags and the plumbing to layer
mod JSON files on top of base content.

### Files changed

1. **game/main.py** — Added `--data-dir` and `--mod-dir` CLI arguments.
2. **game/systems/data.py** — `Content.__init__` gains `mod_dir` param. New method
   `_load_table_with_mod()` loads `mod_dir/<table>.json` for each content table and
   calls `_merge_table()` to overlay mod entries by id (duplicate ids warn but mod wins).
   New method `_merge_table(base_entries, mod_entries)` merges with id-based overlay.
3. **game/systems/world.py** — `World.__init__` gains `mod_dir` param, passes to `Content`.
4. **game/engine/scenes.py** — `RunScene.__init__` gains `data_dir`/`mod_dir` params,
   passes to `World`. `Game.__init__` reads `data_dir`/`mod_dir` from `self.args`.
5. **tools/validate_data.py** — `validate_dir()` gains `mod_dir: Path | None` param.
   Validates mod files against the same schema, checks for duplicate ids within mod files,
   warns on unrecognised filenames (must be in CONTRACTS §4), errors on wrong `version`
   field or non-list `entries`.

### Contract changes

`docs/CONTRACTS.md` updated to document `mod_dir` support and the mod file schema:
top-level `version: 1` + `entries` array matching the base table schema.
