## 1. P0.1 — the game crashed every time the player died

**Found by:** sweeping every documented claim against the code (`menus.draw_end_screen` was claimed in
`docs/PROGRESS.md`, `docs/ROADMAP.md` P3.5 and `docs/TICKETS.md`, and did not exist).

**Repro (real output, before the fix)** — a throwaway script that drives the real scene stack; its
permanent form is `python -m tools.qa.death_run` (section 3), which fails the same way on the same
bug:

```
$ MSYS_NO_PATHCONV=1 .venv/Scripts/python.exe C:/Users/dbshe/AppData/Local/Temp/rw_repro_end_screen.py
run started: state=running floor=1 hp=90
top scene: EndScene
Traceback (most recent call last):
  File "C:\Users\dbshe\rogueworks\game\engine\scenes.py", line 888, in draw
    menus_mod.draw_end_screen(surface, self.world, self.victory, self.game.profile, self.menu)
AttributeError: module 'game.ui.menus' has no attribute 'draw_end_screen'
RESULT: CRASH
REPRO_EXIT=3
```

The repro drives the real scene stack — `Game.start_run`, `world.on_player_death`, `Game.end_run()` —
then renders whatever scene is on top. No mocking.

**Why no gate caught it:** a 300-tick headless run stays on `RunScene`. Death, the menus, the meta
shop, the settings screen and the codex were never executed by any check, so the crash survived
every green light and would fire in a player's face on their first death.

**Fix:** implemented `draw_end_screen(surface, world, victory, profile, menu)` in
`game/ui/menus.py` (+ helpers `_recap_lines`, `_history_lines`, `_monster_name`) rendering exactly
what P3.5/P4.5 documented: title, run recap (seed, depth+biome, rooms, kills, essence, fate),
codex counter, bestiary top-3 by kill count, last-3 run history, and the retry/meta/menu list.
Every lookup is defensive — a crash on death is the worst possible bug.

**After the fix (same repro):**

```

run started: state=running floor=1 hp=90

RESULT: end screen rendered OK
REPRO_EXIT=0
```

Frame: 1280x720, 10337 bytes, 8 distinct colours (not blank). Vision audit of the rendered frame
reported: title `THE LANTERN GOES OUT`, both panels legible and non-overlapping, no text clipping —
"the render is clean, with no glitches, clipping, overlapping, or missing elements".

**One defect found by that audit pass and fixed:** the bitmap font has no `(` or `)` glyph
(`FONT_GLYPHS` = 45 glyphs), so the recap's biome line rendered with silent gaps. Changed to
`"floor %d - %s"`. Verified deterministically instead of by eye:

## 2. P0.2 — SLAP #74 and #75 could never close

Both slaps were filed with the acceptance command

```
MSYS_NO_PATHCONV=1 .venv/Scripts/python.exe -m game.main --headless --turns 300 --seed 0..2
```

and `--seed` was `type=int`, so argparse rejected `0..2` and WARDEN recorded
`STILL OPEN - fix did not verify (exit 2)` twelve times between 22:50 and 23:19 — the substance of
both slaps had long been fixed, but the command itself could not run.

**Fix:** `--seed` now accepts the shorthand the docs are actually written in — `INT`, `0..7`,
`0..7..2`, `0,3,7`. Same command, verbatim:

```
$ MSYS_NO_PATHCONV=1 .venv/Scripts/python.exe -m game.main --headless --turns 300 --seed 0..2
=== seed 0  (1/3) ===
  ok=True  errors=[]  violations=[]
=== seed 1  (2/3) ===
  ok=True  errors=[]  violations=[]
=== seed 2  (3/3) ===
  ok=True  errors=[]  violations=[]
SLAP_FIX_COMMAND_EXIT=0
```

Determinism preserved — a range equals three sequential single-seed invocations, run for run:

```
seed 0: standalone exit=0  in-range exit=0  summaries identical=True  ok=True violations=[]
seed 1: standalone exit=0  in-range exit=0  summaries identical=True  ok=True violations=[]
seed 2: standalone exit=0  in-range exit=0  summaries identical=True  ok=True violations=[]
RANGE == SEQUENTIAL (ignoring wall-clock metrics): True
```

(Identical across every summary key except `metrics`, which is wall-clock FPS and never expected to
match. Each seed re-reads the profile from disk so no seed inherits another's banked meta.)

Also fixed while in there: `--log PATH` with a range used to write all seeds to one file (last one
won) — each seed now gets `NAME-seed<N>.json`.
