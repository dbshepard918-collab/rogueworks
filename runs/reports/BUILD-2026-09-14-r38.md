# BUILD 2026-09-14 — r38: randomness-quality gate (RNG-01)

Date: 2026-09-14.  Owner: forge.  Lane: tools/qa + tools/selftest (cross-lane reason stated below).

## Why this round exists

The RNG defect fixed earlier today (`a9529f6`) was invisible to every gate in this repo.
`RNG._next()` had lost two of its three xorshift steps to operator precedence, collapsing the
generator to an **8-value cycle** — `randint(0, 9)` could never return 0, 3, 8 or 9, and 10,000
draws produced 8 distinct values. `main` exited 0, all seven gates were green, and the
golden-seed regression passed the whole time. A broken generator is perfectly *stable*, and
stability was the only property anything asserted. Determinism is not randomness.

## What changed

- **New** `tools/qa/rng_quality.py` — 9 statistical assertions against `game.systems.rng`:
  `random()` in [0,1); >9,000 distinct values in 10,000 draws; `randint(0,9)` reaches all ten
  values; chi-square uniformity over 10 buckets (limit 40, df=9 p=0.001 is ~27.88);
  same-seed determinism; different seeds diverge; no cycle in 100,000 raw draws; `choice()`
  covers its sequence; `shuffle()` permutes. Exit 0 pass / 1 fail / 2 unloadable.
- **`--inject-bug` self-test** — installs the exact historical precedence-bugged `_next()` and
  **requires** the checker to fail. A checker that cannot fail is not a checker.
- **`--source <path>`** — runs the statistics against any `rng.py`, so the defect can be
  demonstrated on real file content rather than a stand-in.
- **`tools/selftest.py`** — new `check_rng_quality` runs the statistics *and* the injected-bug
  self-test, so the gate cannot rot into a vacuous pass. Check count 21 → 22.
- **`tools/_util.py`** — `run_tool_subprocess` gained an optional `extra_args` (default `None`,
  backwards compatible) so a check can invoke a tool's self-test mode.

Self-test detects the historical defect:

```
$ .venv/Scripts/python.exe -m tools.qa.rng_quality --inject-bug
  caught [distinct-values]     8 distinct values in 10000 draws (need >= 9000)
  caught [randint-coverage]    randint(0,9) reached [1, 2, 4, 5, 6, 7] (missing [0, 3, 8, 9])
  caught [uniformity-chi2]     chi2=900000.0 over 10 buckets (limit 40.0)
  caught [no-short-cycle]      cycle of length 8 detected
OK: the checker detects the historical defect (5 check(s) failed as they should)   EXIT=0
```

Exit non-zero on a real reverted file (`--source` on a copy with the precedence bug restored):
`FAILED: 5 check(s) - the RNG is not producing random output` — **EXIT=1**.

**The wired-in proof.** With `game/systems/rng.py` reverted to the buggy form, `tools.selftest`
reported:

```
[FAIL] rng-quality                  5 check(s) red, first: distinct-values - 8 distinct values in 10000 draws (need >= 9000)
22 checks: 21 passed, 0 skipped, 1 failed
```

Note the second line: **only** `rng-quality` failed. The golden-seed regression passed on the
broken generator, which is exactly how the defect shipped. The fix was then restored
(`grep -n "x ^= (x << 25)" game/systems/rng.py` → line 51) and the gates re-run:

```
$ .venv/Scripts/python.exe -m tools.selftest
[PASS] rng-quality                  9 statistical check(s) pass; self-test detects the injected defect
22 checks: 22 passed, 0 skipped, 0 failed | OK: no failures

$ python -m game.main --headless --turns 300 --seed 0      ->  ok=True errors=[] violations=[]  EXIT 0
$ python -m tools.studio.verify_gate --seeds 0 1 2 --turns 300  ->  VERDICT: PASS - all 7 gate(s) green
```
