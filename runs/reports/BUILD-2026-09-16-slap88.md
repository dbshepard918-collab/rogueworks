## What was wrong

Both `tools/qa/regression.py` (`check_balance`, line 243-244) and `tools/qa/fix_balance.py` (`_dominates`, line 84-94) read combat stats (`damage`, `armor`, `crit`, etc.) as **top-level** fields on item dicts. The actual `items.json` schema stores all combat stats inside `effect.{damage,crit,...}` — verified: 73 entries, 0 top-level `damage`/`armor`/`crit`, all non-zero counts live under `effect`. This caused:

- `regression.py` `check_balance` to SKIP (found no stat_fields) while PROGRESS/TICKETS claimed "no balance violations" as verified.
- `fix_balance.py` to report "500 violations fixed" that was unverifiable (it was comparing nothing against price order).

## What was fixed

### `tools/qa/regression.py`
- Line 243-244: changed `e.get(f)` → `e.get("effect", {}).get(f, 0)` for stat_fields discovery
- Comment updated to state the schema location explicitly

### `tools/qa/fix_balance.py`
- `_dominates()` (line 84): changed `a.get(f,0)` → `a.get("effect", {}).get(f, 0)` for damage/armor/crit
- Added `value` comparison as top-level cost (higher value = more expensive = dominated), which was previously missing and caused false domination findings
- NUMERIC tuple kept as-is since `value` is top-level and the others are in `effect`
